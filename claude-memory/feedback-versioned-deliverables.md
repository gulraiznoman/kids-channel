When delivering a document, deck or asset, write each revision to a **new file** with an
incremented version suffix (`- v03.pptx`, `- v04.pptx`). Never overwrite or silently replace
a file already handed over.

**Why:** Asked for this on 2026-09-02 during the Oestrogel brand plan work, after I had
overwritten the delivered deck twice. It destroyed the ability to go back to an earlier
state — when a later round of feedback was regretted, the earlier version no longer existed
and could not be recovered. Also caused confusion about which of several similarly named
files was current.

**How to apply:** Zero-pad the version (`v03` not `v3`) so files sort correctly. Keep the
base name stable so versions group together in the folder. State the new filename explicitly
when delivering, and say what changed from the previous version. If asked to revert, the
older file should still be sitting there.
